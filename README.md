# jolt-bindgen

A binding generator for the [jolt](https://jolt-lang.net) runtime: C headers
in, `jolt.ffi` namespaces out. It reads the headers with clang, so the
compiler decides every type, constant and struct layout, and it writes
namespaces you commit and read like any other source.

## Example

A header:

```c
#include <stdint.h>
#define VEC_MAX_ITEMS 64
typedef enum { VEC_OK, VEC_FULL = 1u << 4 } VecStatus;
typedef struct { float x, y; uint32_t tag; } Vec;
float vec_length(const Vec *v);
```

a manifest, `gen/manifest.edn`:

```clojure
{:headers ["vec.h"]
 :include-dirs ["include"]
 :file-filter "vec.h"
 :ns-names {"vec.h" "vec.ffi"}
 :test-ns "vec.layout-test"
 :macro-prefixes ["VEC_"]}
```

and `jolt -M:gen` writes `src/vec/ffi.jolt`:

```clojure
(ns vec.ffi
  "Generated by jolt-bindgen from vec.h. Do not edit by hand."
  (:require [jolt.ffi :as ffi]))

;;; enums
(def VecStatus {:VEC_OK 0, :VEC_FULL 16})
(def VEC_OK 0)
(def VEC_FULL 16)

;;; constants
(def VEC_MAX_ITEMS 64)

;;; structs and unions
(def Vec-desc [:struct [[:x :float] [:y :float] [:tag :uint32]]])
(def Vec (ffi/layout [:struct [[:x :float] [:y :float] [:tag :uint32]]]))

;;; functions
;; float vec_length(const Vec * v)
(ffi/defcfn vec_length "vec_length" [:pointer] :float)
```

along with:

- `gen/targets/<target>.edn`, what clang saw for each target (see
  [Targets](#targets));
- `test/vec/layout_test.clj`, a test that checks jolt's struct layouts
  against the sizes and offsets the C compiler measured;
- `gen/report.edn`, what was bound and what was left out, with the reason
  for each.

## Use

Needs jolt and clang on the path. A binding project depends on the generator
through an alias in its `deps.edn`, pinned to a commit of this repository:

```clojure
:aliases {:gen {:extra-deps {jlt-commons/jolt-bindgen {:git/url "https://github.com/noonian/jolt-bindgen"
                                                       :git/sha "<commit sha>"}}
                :main-opts ["-m" "noonian.jolt.bindgen.main" "gen/manifest.edn"]}}
```

and regenerates with `jolt -M:gen`, run from the project's root. Commit the
generated namespaces, the layout test, `gen/targets/` and `gen/report.edn`,
like a lockfile: a regeneration after an upgrade then shows the API change
as a diff. `gen/work/` holds the probes and intermediate files and can be
ignored.

To work on the generator itself, point the alias at a checkout with
`:local/root` instead.

## The manifest

| Key | Default | Meaning |
|---|---|---|
| `:headers` | required | Headers to parse, as they are included (`"SDL3/SDL.h"`). |
| `:include-dirs` | none | Include directories, relative to where `jolt` is run. A vector, or a map from a target or an operating system (`:darwin`, `:linux`, `:windows`) to a vector. |
| `:defines` | none | Preprocessor definitions, each as clang's `-D` takes it (`"NAME"` or `"NAME=1"`). |
| `:file-filter` | required | A declaration is bound when the path of the header declaring it contains this string. What those headers include from elsewhere is used for types and not bound. |
| `:skip-headers` | `#{}` | Header file names to leave out although they match. |
| `:ns-prefix`, `:strip-prefix` | none | How a header names its namespace: `SDL_video.h` with prefix `"sdl3.ffi"` and strip `"SDL_"` is `sdl3.ffi.video`. |
| `:ns-names` | none | A header file name to its namespace, outright. |
| `:macro-prefixes` | none | An object-like macro becomes a constant when its name starts with one of these. |
| `:macro-exclude` | `#{}` | Macro names to leave out although they match. |
| `:blocking` | `#{}` | Names of functions that may block. Each is bound with `:blocking`, and its `const char *` parameters as pointers. |
| `:targets` | none | Other targets to extract from this machine (see [Targets](#targets)). |
| `:source-label` | none | The library and version, for the namespaces' docstrings (`"SDL 3.2.0"`). |
| `:test-ns` | required | The namespace of the generated layout test. |
| `:project-dir` | `".."` | The project's root, relative to the manifest. |
| `:out-dir`, `:test-out` | `"src"`, `"test"` | Where the namespaces and the layout test go, relative to the project's root. |
| `:targets-dir`, `:report-out`, `:work-dir` | `"targets"`, `"report.edn"`, `"work"` | Where the target records, the report and the intermediate files go, relative to the manifest. |

## What is bound

- **Functions** as `ffi/defcfn` forms, each under a comment giving its C
  signature. A struct passed or returned by value is bound `:by-value`. A
  variadic function is bound with the bare `:&` marker.
- **Structs and unions** as an `ffi/layout` and its descriptor. One named
  only by its typedef takes that name. One the headers declare and never
  define is listed in the report under `:opaque-records`, and is a pointer
  wherever it appears.
- **Enums** as a map and one constant per enumerator. An enum nothing names
  still gives its constants.
- **Object-like macros** as constants, with the value and type the compiler
  gives them. A generated C probe is parsed by clang and never run, so this
  works for a target other than the machine generating.
- **Callback typedefs** as signatures for `ffi/callback`.
- **Typedefs from other headers**, such as `time_t`, as the type clang
  resolves them to for the target.

## What is not

Each of these is left out and named in the report with the reason:

- a struct or union with a bitfield or an anonymous union, and anything that
  holds one by value;
- a function with a `va_list` parameter, or one that passes a union by value,
  alone or inside a struct;
- a variadic function that is also blocking, or that passes an aggregate by
  value, which jolt does not combine with `:&`;
- a `static` function, which the library does not export;
- a global variable;
- a callback type with no jolt spelling;
- a wanted macro that is not a constant expression.

## Targets

Generation has two stages. Extraction runs clang for one target and writes
what it saw to `gen/targets/<target>.edn`: the declarations as clang spells
them, the macros and the struct layouts it folded. Emission merges every
file in that directory into the namespaces and needs no compiler. A binding's
targets are the files there.

A run always extracts the machine it is on. `:targets` in the manifest names
others to extract from the same machine, which works when the headers need
no system header of the target's (`stdint.h` and `stddef.h` come with clang;
`stdio.h` and `time.h` do not), and such a file is marked `:cross? true`.
A target that cannot be parsed from here is named in the report, and is
extracted by running the generator on that platform and committing its
file; a file extracted on its own platform is never replaced by a view of
it from another. `--check` extracts the current machine afresh, compares
it with the file on record, and exits non-zero when they differ, which is
the job for a CI run on each platform:

```sh
jolt -M:gen --check
```

The targets are `darwin-arm64`, `darwin-x86_64`, `linux-x86_64`,
`linux-arm64`, `windows-x86_64` and `android-arm64`.

With one target the namespaces are that target's definitions and nothing
else. With several, what the targets define alike is written once, and what
they define differently (a `time_t` that is a `long` here and a `long long`
there, a macro behind an `#ifdef`) is chosen when the namespace loads, by
`bindgen-target`; the report lists each under `:divergent`. A function
only some targets declare is written for all of them, since jolt binds a
function when it is called. The layout test checks the target it runs on.

Such a namespace refuses to load on a target nobody extracted: a binding
that was never checked there is a guess at an ABI. In an emergency
`JOLT_BINDGEN_TARGET=linux-x86_64` loads it as that target anyway, and the
layout test then says how far the guess is off.

## Status

Early, and shaped so far by three bindings: SDL3, Jolt Physics (through
joltc) and Dear ImGui (through cimgui). The manifest keys and the generated
output may still change. It has been developed on `darwin-arm64`; the
other targets have been extracted from there and not yet checked on their
own platforms, and Android detection in particular is untested.

## Development

The tests run the headers under `test/fixtures` through the generator, build
one into a shared library and call the generated bindings, so they need
clang too:

```sh
jolt test
```
